# 同事件竞品对比 v0.1：实现与验收

## 首期范围

入口：账号矩阵底部“同事件竞品对比”→“开始对比”。
人工从自有账号及其关联竞品中各选一篇，核对完整发布文案，勾选同一具体事件后对比。
确认仅在当前组件内存有效，不写入数据库或事件分组。相同主题不能自动当作相同事件。
账号身份和关联关系取现有矩阵，服务端在分析前后均校验。

基础对比读取作品发布时间、清理后文案、标题字数及问句/感叹/数字特征。
发布顺序仅限两篇所选作品，不宣称全平台首发。
清理沿用 caption-cleaned-title-v2，保留全部叙事句，不改采集原文。
已有封面标签按当前封面地址哈希和观测截止绑定，仅展示文字密度、构图、色彩及来源版本。
不下载或显示远程封面，没有有效标签时如实标缺失；URL哈希不代表图片字节校验。

切入角度及差异线索需单独点击“分析切入角度”，最多一次已配置模型请求，无重试。
仅发送两篇清理后的文案，不发送图片、互动数据或账号隐私信息。
严格结构化响应，校验每个引文为输入文案中的连续原片段，补作品ID、字段和SHA。
每条差异线索必须引用竞品片段，片段逐字已在自有文案出现时拒绝。
引用校验不能代替语义核验；仍需编辑核实角度判断及同义表达是否实际已覆盖。
结论只限两篇文案，不宣称自有账号全部作品未覆盖，也不是全文事实核验。
模型关闭或调用失败时基础对比仍可读，不用规则文本冒充模型结论。

## 接口与一致性

- GET /api/monitor/event-comparison/posts：account_id，days（1—365），q（最多100字符），page，page_size（最多50）；稳定按发布时间、作品ID分页。
- POST /api/monitor/event-comparison：owned、competitor（各含account_id/post_id/source_sha256），confirmed_same_event=true，可选analyze_angles=false。
- POST只是计算，无持久化。GET和普通基础对比均不调用模型。
- 来源库使用只读连接及一致性事务，不新增表、不迁移，不修改监控/采集/快照任务。
- 作品必须属于所选账号且有效，发布与首次发现均不得晚于读取截止。
- 输入绑定包含账号身份、完整原文、发布时间、首次发现、封面地址及提取版本。
- 模型调用结束后重新校验材料，变化返回409；前端清空旧结果与选择，要求重新确认。
- 角色/关系或材料错误不会自动扩大候选、切换账号或全库回退。
- 数据库缺失返回不可用，不自动建表。

## 互动口径

逐阶段读取1h、6h、24h、72h、7d快照。要求采集时间/入库时间有效、记录年龄与实际年龄一致、年龄落在既有阶段容差内。
同阶段两篇实际年龄差还需不超过 min(阶段容差，目标年龄的10%)，否则标“暂不可比”。
显示双方实际年龄、采集时间、四项原始计数及“累计观察值”。
真实0保留为0，字段缺失显示破折号；无有效观测显示“无有效快照”，不补0。
不汇总为表现分，不用累计量推断传播优劣或因果。

## 变更文件

- api/services/event_comparison_service.py：只读材料、分页、绑定、观测配对、已有封面特征、显式模型分析和引文校验。
- api/routers/monitor.py：两个独立接口与矩阵身份/关系校验。
- webui/src/lib/eventComparison.ts：类型及客户端。
- webui/src/components/monitor/EventComparison.tsx：原位双栏选择、确认、基础/模型对比、快照和证据展开。
- webui/src/components/monitor/AccountMatrix.tsx：增加独立对比区；原账号管理和档案保持原入口。
- tests/test_event_comparison.py：30项隔离测试。
- tools/accept_event_comparison.py：合成测试库、真实服务、模型替身的浏览器验收。
- tools/accept_account_style.py：旧版回归明确选择真实v0.1样本，避免最新v0.5记录被误当旧样本。

本轮只完成源码与独立构建，未覆盖api/webui，未重启运行中的监控服务；检查时运行服务还没有新增接口。

本轮没有数据库迁移、正式库写入、提交、推送或远程机器操作。

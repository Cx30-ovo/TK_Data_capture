# 疑似同事件候选发现 v0.1

日期：2026-10-23。

## 已实现

账号矩阵 → 同事件竞品对比 → 选择自有与关联竞品 → 查找候选。按双方文案字面重合提出疑似配对，展示账号、发布时间、完整清理文案及共有原文片段。选入后清空旧结论与人工确认，继续走现有确认与对比流程。候选不是事件判定，不自动执行模型分析，不持久化配对或创建事件组。

### 文件

- `api/services/event_candidate_service.py`（新增）：只读一致性读取、字面门槛、计算上限、稳定排序及分页。
- `api/routers/monitor.py`：新增候选GET，复用矩阵角色/关联验证，并在读取前后核对。
- `webui/src/lib/eventComparison.ts`：候选类型与客户端。
- `webui/src/components/monitor/EventCandidates.tsx`（新增）：候选窗口、显式检索、双栏文案、依据、分页、错误及空状态。
- `webui/src/components/monitor/EventComparison.tsx`：候选选入，保留人工确认，409时失效候选查询。
- `tests/test_event_candidates.py`（新增）：候选、只读、来源绑定、资格过滤、预算、分页及关联角色测试。
- `tools/accept_event_comparison.py`：接入真实候选服务和隔离数据，验证人工确认及超限/空态恢复。
- 本文档。

### 接口

`GET /api/monitor/event-comparison/candidates`

参数：`owned_account_id`、`competitor_account_id`；`days`默认7，范围1—30；`page`默认1；`page_size`默认5，最大20。前端提供3/7/14/30天。

响应携带版本、截止时间、扫描篇数、total、页码、页大小、items、未截断标识、零模型调用和限制说明。每对保留现有作品身份/SHA，点击对比时仍核对实际输入变化。对外不展示内部排序分数或同事件概率。

### 规则与上限

- 已采集且active、账号绑定，发布时间早于读取截止、首次采集不晚于截止。每次GET单独一致性事务，不跨页承诺固定快照。
- 双方发布时间差不超过72小时。
- 清理文案规范化后取4字连续片段：至少3个不同共有片段，且占较短文案片段集合至少12%；过滤一组常见报道套话。再要求原文中存在可展示的连续共有片段。此规则不是语义识别，可能误配和漏检。
- 排序按共有4字片段Jaccard比例降序、发布时间差升序、双方作品ID稳定顺序。归一化的候选仍需原文共有片段，大小写或标点变化可能漏检。
- 每账号最多500篇；两侧笛卡尔积最多20000对；单篇原始文案最多2000码点；两侧清理文案总长最多100000码点。超限422明确拒绝，不静默截断，不自动放宽门槛。
- CPU比较在工作线程执行，不阻塞应用事件循环；不新建后台持续任务。
- 前端不在进入页面时主动查询候选；点击查找后按账号/窗口/页码隔离缓存。没有自动轮询；再次查找可读取新数据。
- 页面错误隐藏旧候选。来源变化仍由原对比409机制阻断，不自动确认或改写输入。

# 监控账号评论取消数量上限

日期：2026-11-04。本次覆盖上一版评论采集的数量上限和续采行为；上一版报告、截图及构建保留。

## 完成内容

- 主评论和子评论不再设置总条数上限，移除界面数量输入框。保留自动采集开关和子评论开关，默认政策仍为关闭自动采集、开启子评论选项；本轮未替用户启用任何账号。
- 旧政策中的 max_comments、max_replies 不再参与读取结果或采集判断。旧客户端仍可提交这些非负整数字段，但服务端忽略且不保存它们，避免旧的50/100或200/500限制继续生效。
- 逐页验证并保存整页数据及游标，使用既有 collections.payload 保存进度，无新增表、列、索引、迁移。每页评论与游标在同一SQLite事务中提交；父子关系冲突会回滚整页，不推进游标。
- 先遍历主评论分页，再逐个主评论遍历子评论分页。即使之前显示子评论数为0，也检查其回复接口；不依赖计数跳过。回复队列利用已保存主评论和既有主键检索，不把所有评论、主评论ID或回复游标列表积存在内存中。
- 每个时间片最多10次请求、120秒，单请求超时30秒，每次请求间隔5秒；这些限制仅用于让出浏览器，不作为总量上限。正常未完成任务至少间隔60秒续采，普通错误至少间隔30分钟重试；风控、暂停、浏览器恢复遵循既有统一处理，不修改冷却设置。
- 没有新作品、未到账号发现时间时，监控循环仍可续采一项到期评论任务。先执行既有快照/账号发现，再处理评论时间片；按到期时间轮转，不新增独立后台工作进程。
- 超过7天的未完成队列继续采集，不因作品年龄丢弃。完成主评论及子评论遍历后，近7天作品间隔6小时刷新；超过7天停止定时刷新，已有评论保留，仍可手动更新。以前已经标记 expired 的旧任务未批量激活，可通过作品详情手动补采。
- 取消和暂停保留最后成功页。重启后的新采集实例读取保存游标；异常退出时沿用既有10分钟运行租约恢复机制。达到时间片预算显示“未完成，进度已保存”，不冒充完成。
- 评论正文不再截为20000字符。昵称继续脱敏，保留正文、时间、点赞和父子关系，不采集个人主页。

## 生效状态及限制

前端已切换，当前运行后端的接口文档尚无评论接口，需要重启本地后端后生效。本轮只读检查显示检查当时普通采集和监控操作均未执行；未暂停、重启后台，也未修改账号评论政策。

“全部”指按接口持续分页直到平台返回无更多的本轮可见内容。隐藏、已删除、权限受限或平台未返回的数据不可取得；平台列表在长时间遍历期间变化也可能影响覆盖，不能将分页完成宣称为平台绝对全量。没有对真实平台做成功率或完整性验收。长期不设数量上限会增加采集耗时和侧库占用，本轮未新增清理保留期，也不删除原评论数据。

已有作品自动入队范围仍为监控发现的新作品；本次不扩大为所有历史作品自动批量补采。已有作品可在详情手动补采，未完成后自动续采要求监控服务运行、账号及评论政策启用，且不处于暂停/冷却中。

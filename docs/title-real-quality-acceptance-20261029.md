## 已证实问题

### D1：原文片段 ID 被模型错误拼接

证据：`tmp/title-real-20261029-01/2-response.json`，JSON 路径：

- `body.editorial_pipeline.facts[0].unit_ids[0]` 为输入的合法片段 ID，以 `9cef7214…` 开头。
- `body.quality.decisions[0].primary_fact_id` 以 `f19cef7214…` 开头，模型把独立事实短 ID `f1` 拼在片段 ID 前，并形成另一个满足长度规则的 64 位字符串。
- 第 2 条同样引用该错误 ID；第 3 条以 `f288eeb57…` 开头，与 `f2` 及原片段 ID 的拼接模式一致。
- 三条均触发 `invalid_plan`，保留数量 0。

服务端拒绝非法引用符合预期，但输出契约同时要求模型处理事实短 ID、计划短 ID、64 位片段哈希，真实模型未稳定遵守。现有模拟用例用精确 ID 自动装配，没有覆盖本次真实格式失误。

本次结果没有保存被过滤标题的完整正文，仅保留诊断和事实规划；因此不能进一步判断三条标题的内容质量。不能把模型自查 `keep` 当作服务端或人工核验通过。

建议最小修复：模型输入输出使用服务端分配的短片段 ID 或索引，服务端精确映射回真实来源及 SHA；保留计划/独立事实关联校验，不通过猜测或模糊纠错接受非法 ID。将本次真实错误 ID 固定为回归样本。

### D2：失败阶段缺少可定位诊断

证据：`1-response.json`、`3-response.json` 只返回相同通用 502 错误；标题失败记录只登记失败状态，没有具体失败规则、字段路径或安全脱敏的阶段输出。检查本轮运行日志也未取得具体校验分支证据。

结论：能确认两次进入阶段关联校验后失败，**不能确认分别是 unit ID、事实重叠、限定词、计划还是复核记录导致失败**，不能统一归因为 D1。

建议最小修复：对阶段校验增加稳定错误码及字段路径，并保留有范围、受限长度的脱敏诊断（不记录模型地址、凭据和原始请求头）。拒绝时依然不发布标题、不自动重试。是否保留被过滤候选正文需在修复方案中明确保存范围与用途。

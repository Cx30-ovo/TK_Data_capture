# 自动竞品分析：计算量与批次上下文修复

## 原因和修复

原检索先以两个账号作品数量相乘检查 20,000 对上限，随后才按已有的发布时间差不超过 72 小时规则过滤，造成无需实际比较的跨期组合也占用预算。

新检索版本 `event-candidates-literal-v0.2` 用时间索引先选出符合既有时差规则的组合，再以实际需比较的组合数检查同一安全上限。72 小时边界包含在内；字面匹配、排序、作品数和文本安全上限保持不变。超限明确拒绝，提示实际计算量和上限，不截断、不自动缩小窗口。响应增加 `evaluated_pairs`，冻结规则记录 `pair_budget_scope=within_publication_gap`；旧检索快照不重算、不覆盖。

前端在窗口、分析数量或账号变化后清除当前选中结果和错误；新启动提交前清除上次结果。历史记录仍可主动打开，并明确展示该批次自己的窗口、创建时间和账号，不以当前选择条件解释旧结果。检索范围与模型分析数量的区别在控件下说明。

## 验证与应用

- 后端检索、冻结批次、自动分析、双篇对比和反馈测试：152 项通过。包含新时间索引与原全组合算法结果和排序等价性、72 小时边界、实际计算量准入、超限不截断及只读检查。
- TypeScript 和 Vite 构建通过。独立输出 `webui/dist-comparison-budget-20261026-01`，构建阶段共享目录的路径集合与逐文件 SHA 不变。
- 隔离浏览器验收 22/22 通过：`tmp/comparison-budget-browser-20261026-01/results.json`，含窗口切换、超限失败、历史回看、深浅色和三档宽度等。真实模型请求为 0；测试推断使用内存模拟。
- 当前真实材料只读检索记录：`tmp/comparison-budget-20261026-01/readonly-discovery.json`。窗口随时间滑动，作品数、需比较对数会随截止时间小幅变化；当次召回 7 对，不代表平台全量或已确认同事件。
- 已保全原共享构建目录至 `tmp/comparison-budget-20261026-01/webui-before`，应用新产物时先资源后入口，保留旧资源。
- 核实采集和自动分析无在途任务后，临时暂停监控并重启指定本地后端。运行核对见同目录 `live-check.json`，监控暂停状态与重启前一致。未启动真实分析，未修改采集配置、数据库结构或已有分析结果。

## 文件范围和局限

源码：`api/services/event_candidate_service.py`、`webui/src/components/monitor/AutomaticComparison.tsx`；验证：`tests/test_event_candidates.py`、`tools/accept_model_comparison.py`；另有本文档和独立构建/验收产物。

检索仍按字面线索和 72 小时时差召回，不包含全量语义发现。每账号 500 篇、清理后总文本 100,000 和实际比较 20,000 对等限制仍可能拒绝更大输入。模型分析需用户点击启动，未自动触发。

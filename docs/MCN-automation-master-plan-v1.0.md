# MCN／媒体账号自动选题与内容决策平台完整方案 v1.0

日期：2026-10-26。本文为设计方案，不代表已实现、不启用调度、不调用模型、不执行建表或迁移。适用于当前本地开发；不涉及远程机器。早期开发计划仅作为历史记录，本方案按当前代码能力重新划分阶段。

## 1. 产品目标与最终工作方式

建设面向MCN和媒体账号的自动内容决策工具：持续观察自有账号与竞品，从事件变化、竞品覆盖差异、账号定位和历史节点中自动发现选题，生成可执行策划及标题，结合发布后数据持续评估和训练专用模型。

主流程：持续采集 → 增量提取 → 自动归并事件 → 竞品分析／热点观察／历史节点 → 选题机会 → 账号适配与排序 → 选题卡与3—5个标题 → 发布关联 → 同期复盘 → 反馈与训练 → 新模型评估和灰度。

最终不是让编辑反复选两篇做分析，而是让系统主动提交选题，编辑处理例外、设定方向和最终审核。低风险、证据充分且已通过独立评估的任务逐步自动执行；事实冲突、输入失效、重大敏感议题和低把握案例进入例外队列。首次上线不自动操作发布账号；自动发布是后续独立集成范围。

模型承担事件理解、角度分析、选题判断、标题策划；程序负责时间、计数、证据绑定、任务调度、预算和版本，避免模型凭空计算或自行宣称事实通过。

## 4. 统一数据与证据基础

保留原始作品和四项互动观测；每条分析引用记录账号ID、作品ID、原始来源、字段路径、片段、片段SHA、来源SHA、采集／发布时间、材料等级及提取版本。清理口径沿用当前已确认规则：保留正文内话题文字、去掉#，清理尾部标签和采编信息，不擅自截成第一句话。

材料等级明确区分：标题／发布文案、封面可见内容、视频转写、完整报道、外部核实材料。当前只有文案就只作文案级判断。视觉模型可识别封面表达，但封面文字本身不是事件真实性证明。

保存published_at、first_seen_at、captured_at、ingested_at及状态版本；回放预测和评估时只能使用决策时已可见的数据。事后补采的数据不能回填成当时已知事实。0为真实零，null为缺失，不把互动计数当播放量或曝光。

原文变化、来源排除、事件拆分或账号身份变化触发依赖失效；重新计算受影响结果，不静默保留旧的“有效”结论。

## 5. 账号档案与增量处理

档案分三层：人工明确的业务定位／约束；系统计算的窗口统计；模型带引用的风格推断。主题偏好、长度和措辞、问句／数字／情绪表达、封面构图等分别记录，不把推测受众说成真实用户画像。

新增或修改作品 → 生成逐篇内容指纹与结构化特征 → 更新对应小批分析 → 更新事件与档案。批次输入完全一致才复用，模型／提示词／Schema变化分别版本化。阶段性从原始材料重新校准，防止旧摘要层层累积失真。

近期、长期画像独立；展示窗口总量、实际使用量、样本上限、缺失和更新时间。后续逐步从500篇样本分析发展到受预算控制的逐篇增量特征，不能简单靠扩大上下文强塞全量历史。

## 6. 自动事件发现与归组

先以时间、实体、地点和关键词召回候选，再补充本地语义召回与重排，最后由模型作结构化事件判断。延续已验收的字面检索作为可解释基础，规则版本和输入快照保留。

模型输出same_event、related_topic、followup、different_event、insufficient_material等关系，并给出双方原文依据。相同主题、同一地点、相似措辞不足以归为同一事件；持续事件用主事件及进展节点表达。

归组必须验证整个事件核心实体、行为、时间和地点的一致性，不能因为A像B、B像C就把A/B/C无条件合并。模型不确定时不强行归组；自动合并保留版本、来源与回退能力，拆分后使旧比较和选题重新检查。

高把握归组阈值须由带标签验证集标定，不能用模型自报“95%”当可信概率。初期影子运行对照人工样本，达标后开放低风险自动归组。

## 7. 自动竞品分析：选题的核心输入

对每个事件聚合自有与关联竞品的作品，不局限一对一：

| 分析维度 | 输出 | 边界 |
|---|---|---|
| 发布时间 | 各账号第一篇、后续更新、发布时间差 | 只称已采集范围内首发；采集时间不代替发布时间 |
| 覆盖情况 | 自有已覆盖、竞品新增、待核实缺口 | 未发现不等于真正未报道，先检查采集健康与覆盖 |
| 内容差异 | 核心进展、事实补充、角度、背景、措辞 | 各类分开，背景细节不强行包装成新角度 |
| 标题／封面 | 长度、结构、用词、数字、可见视觉特征 | 文案和封面标题分别记录；无缓存不自动假造 |
| 同期表现 | 相近发布年龄的原始观测和变化 | 缺快照不可比，不直接推断标题导致互动变化 |
| 来源独立性 | 原创／转载线索、相同素材链、独立来源数 | 同一素材转发不按多个独立信源抬高热度 |

重点生成四类机会：竞品有明确新信息而自有未见覆盖；双方已发但出现值得补充的新进展；同事件适合本账号的独特服务性／解释性角度；旧题因新事实需要跟进。只复制竞品标题、表述差异和无来源推测不进入高优先级。

采集失败／风控／账号暂停期间，缺口标“覆盖不足，不能确认”；不把采集缺失奖励为选题机会。

## 8. 热点观察与预测

观察状态：萌芽、上升、当红、持续发酵、退潮，另有“数据不足”。依据独立账号覆盖增量、作品增长速度、可比互动增量、新事实到达、持续时间等计算。加入最小样本和滞回规则，避免少量更新导致状态跳变。异常计数回落不直接作为负增长结论。

观察是对已经发生的数据的描述；预测是对未来24小时、已监控范围内是否达到冻结热点门槛的判断。页面分区展示，不能用“当前当红”充当提前预测命中。

预测首先建立简单排序／规则、逻辑回归或树模型基线，再训练专用时序／排序模型。LLM可以提取事件语义特征，不直接用它的自评分冒充校准概率。没有播放量和全平台数据时，只预测可观测范围，不声称预测全网流量。

## 9. 自动选题、排序与标题生成

机会先过硬门槛：来源可追溯、事件未混并、时效有效、没有事实冲突、账号定位匹配、采集覆盖允许判断。再按新增信息价值、账号适配、时效、受众服务性、差异化、制作可行性、可靠性和可核实风险排序。预测分数是参考项，不是选题价值的唯一依据。

模型输出结构化维度与说明，排序策略可版本化，页面不展示伪精确“爆款概率”。初期可用明确策略形成基线，反馈积累后再训练排序模型，而不是让模型编一个不可验证总分。

每张选题卡包含：事件与目标账号、为何现在值得做、核心角度、目标受众推测、事实与引用、必须核实的内容、建议形式、素材及封面方向、有效期和覆盖限制、3—5个标题及各自独立引用、当前采用状态、输入／模型版本。

标题生成依据事件证据、该账号档案、编辑目标和禁用表达。候选可分别采用信息直给、解释服务、问题解答等结构，不仅替换同义词。自动检查事实引用、时间数量实体、未证实断言、风格长度、重复与禁用表达。文字合法与引用可定位由程序验证，实质事实判断仍按材料等级处理。材料不足允许少于3个或不生成，不凑数。

生成默认不引入未经引用的新事实，不照搬竞品表达；以账户风格指导表达，而非模仿特定账号的独家素材。模型关闭或失败时保留旧结果、显示状态，不用模板假装模型生成。

## 10. 历史日历

明确事件发生日期、作品发布日期、纪念／计划节点，缺少事件日期依据时仅标“历史作品索引”，不能生成周年事实。时区和日期精度一并保存。

对今日、未来7／30天节点，结合地域关联、当下新进展、账号适配、可获取素材、服务价值和日期可靠性排序。每条说明“为何今天值得做”，可联动近期热点；纯粹日期相同不自动排高。

节点及背景库只接入明确来源；历史材料先核日期和关键事实再作为生成依据。先从现有可核验历史材料起步，外部新闻／日历来源另行配置，不默认开启全网抓取。

## 11. 发布关联与复盘

编辑采用、拒绝、暂缓、修改的原因结构化记录。实际发布后关联平台作品ID、最终标题／封面、账号、发布时间、选题卡和版本。自动匹配只作建议，低把握或多匹配不能强行关联。

按相同发布年龄、账号历史基线与内容类别比较结果，保留原始四项计数、采集时间和缺失。编辑采用不等于成功，互动高不等于事实正确；发布时间、事件本身、平台分发等混杂因素不可忽略。无控制实验不宣称某个标题造成提升。

复盘输出策划与成稿差异、可比结果、修改偏好及后续机会。没有曝光／点击数据时不能计算真实CTR；先做可观察结果分析，未来可通过明确的实验设计衡量因果效果。

## 12. 专用模型训练

最终目标包含真实训练，不停留在提示词配置。默认基于合适的预训练模型做领域适配和监督微调，不从零训练基础大模型。

| 训练任务 | 数据 | 主要评估 |
|---|---|---|
| 事件识别／归组 | 同事件、相关主题、后续进展、困难负例与漏检 | 配对Precision/Recall/F1、簇纯度、误合并率 |
| 竞品差异分析 | 双方原文、结构化差异、编辑纠错 | 引用真实性、差异分类、事实一致性 |
| 选题排序 | 展示批次、编辑选择／拒绝／修改、上下文 | 排序质量、盲评、采用率与选择偏差分析 |
| 风格标题生成 | 账号历史、事实证据、标题修改和偏好对 | 事实错误率、独立风格盲评、重复度与编辑改写量 |
| 热点预测 | 冻结时点特征、未来24小时可观测标签 | Precision@5、覆盖、召回、校准、提前量 |

文本与视觉继续按当前配置共用同一多模态模型服务；不同任务可使用统一基础模型的任务提示或适配器，不要求每个账号独立训练一套大模型。语义检索若需embedding，应单独核对接口能力，不假定现有生成接口支持。预测任务可以使用独立训练的小模型，不必强行由大语言模型承担数值预测。

训练阶段：建立现有模型／规则基线 → 清洗去重和编辑标注 → 封存验证／测试集 → LoRA／QLoRA等领域微调（按硬件适配） → 同输入盲测对照基础模型 → 影子运行 → 小范围灰度 → 逐步扩大自动化。偏好优化与持续训练在已有足够高质量偏好数据后再引入。

训练集按时间、事件簇、转载链分割，避免同事件换个标题进入测试集；账号风格评估另做跨时间及跨账号测试。同一事件跨切分边界采用隔离窗口或整簇剔除／归侧规则，不仅按作品日期粗切。

模型生成、模型互评和自动通过的内容不能直接作为高质量标签；训练数据保留人工／观测／合成标签来源。拒绝内容也可能因资源或排期，不自动当成质量差。需要记录系统展示了什么，避免只学习被编辑看到并采用的样本。

模型和数据集版本包含基础模型／适配器、数据集SHA、时间范围、提示词、Schema、评估集、训练配置及结果。旧版本可回退，不在生产环境按每次反馈在线自我改写。业务分析数据能否用于训练需另行核对授权。当前GPU、基础模型许可、上下文与吞吐尚未核验，不能承诺训练工期或费用。

## 13. 70%热点预测验收

沿用既定方向：已监控范围、未来24小时、每日Top5、连续30天前瞻验证，目标150个有效且不重复凑数的预测，Precision@5目标≥70%。这是待验证目标，不是当前能力。

预测发布前固定事件身份、可见输入、模型版本、预测时间、结果窗口和排序；测试开始前冻结热点门槛、独立来源定义、事件去重、缺失处理及每日推荐时点。不得看完结果后调整门槛。

热点标签建议同时考虑独立来源扩散与按账号／发布年龄归一的互动增长，门槛在训练／校准期标定，不能从测试期分位数反算。具体K个独立来源及增长分位阈值尚需依据现有覆盖定标；只有两个监控账号时不能凭空要求三个独立账号，也不能把两家转载当两条独立信源。标签未冻结前不开始正式70%验收。

150个有效预测中至少105个命中，仅表示样本命中率达到70%，还要报告置信区间；不等于真实长期命中率下界已达70%。

每日不足5个可预测新事件如实输出，不强行凑数。必须同时报告推荐覆盖率（实际发出／计划150）、结果可观测率、无法判定数量、有效样本命中率与保守口径（命中／全部已发出）。缺失结果不能直接当命中或悄悄剔除。未凑齐既定有效样本则报告验收未完成，不宣称150条通过。

同事件在评估期不重复累计命中，已热事件不能再算提前预测；真正独立的新进展需预先固定拆分规则。对照相同候选全集和同一时点的简单热度排序基线；同时报告漏报、误报、提前量、召回和业务覆盖，不仅挑选容易的事件。基线、模型与人工测试集相互隔离。

## 14. 任务、预算与可靠性

GET只读，不启动模型或创建分析；人工或自动调度写入持久任务，再调用模型。任务状态建议queued/running/succeeded/failed/blocked/stale/cancelled，包含输入指纹、去重键、租约、重试计数、预算、产物及失效原因。断点恢复不重复生成同一输入。

采集与分析解耦。采集新增／更正后只发出待分析信号，分析防抖合并小批；无变化不调用。采集风控和冷却沿用原有配置，分析任务不能为了“缺数据”自行解除冷却或提高采集频率。

建议试运行上限：每轮最多20个待判候选组、10个事件更新、5张选题卡；最多20次模型请求／轮、100次／日；累计输出上限4万token／轮、20万／日。以上是待容量测试的初始配额建议，不是已启用配置或成本承诺；原账号档案更新也计入统一日预算，不能多个模块各自叠加。

每次请求按实际模型tokenizer计算输入、模板、视觉输入和输出预留，超过上下文先拆批；只合并结构化事实及引用，不无限追加旧摘要。按输入SHA、模型／提示词／Schema／账号档案版本复用有效结果。

失败保留旧的成功版本并标注时间；证据错配不保存新结论，来源变化标stale。默认不自动重试内容校验错误；网络类重试次数有限、计入预算并绑定同任务。全局暂停分析、每日硬上限、并发上限和熔断均由程序控制。模型开关关闭时不调用，不生成伪结果。

## 15. 存储与迁移设计方向

采集库保持原始作品与快照职责；现有账号矩阵、反馈、检索批次元数据继续保留。建议新增独立内容决策域存储，不把事件状态塞进原始采集记录，也不滥用按账号周期统计的douyin_topic_profiles充当事件簇。

逻辑对象包括事件及成员／修订、分析运行、选题机会、选题卡及修订、编辑反馈、分析任务、发布关联、预测／结果标签、数据集／模型版本。它们是领域对象，不代表本轮批准同数量数据库表。

首期优先评审事件、事件成员、分析运行／任务、机会、选题及修订、编辑反馈所需最小表集；证据和绑定可先用版本化JSON。发布／预测／训练实体按后续批次新增。物理表、索引、外键、约束、备份和回滚必须在实现批次单独列清，不在本文执行。

跨库使用稳定身份和SHA关联，不声称具备跨库事务。跨库操作以任务状态和可重跑幂等处理，不做部分失败后静默覆盖。新增迁移需先在副本演练，记录旧表Schema、行数和逻辑哈希；正式迁移单独确认窗口与备份。

## 16. 自动化放权与验收

| 级别 | 系统行为 | 开放条件 |
|---|---|---|
| A0 影子分析 | 自动算但不替代现有编辑决策 | 流水线、证据、预算和日志稳定 |
| A1 自动建议 | 自动产出机会、选题卡和标题 | 引用可定位、失败隔离、事实错误有可控边界 |
| A2 低风险自动处理 | 自动归组／排序／更新常规建议 | 独立验证集达到冻结门槛，具备回退与漂移监控 |
| A3 例外审核 | 常规工作自动完成，编辑只处理异常与最终发布策略 | 前瞻业务评估稳定，各任务单独达标 |

事件识别、选题、生成、预测分别验收，不能因一个指标达标全系统放权；人工工作量通过“每百条建议复核耗时／需介入比例／错误返工”衡量，避免不断增加点击任务。

每批验证功能、证据与来源失效、幂等并发、任务恢复、预算／零模型开关、空数据／风控覆盖不足、三宽度深浅色和键盘。构建继续独立目录、先验收、备份旧前端后切换；需要新增任务或数据库迁移时独立审核。保留目前所有检索、反馈和对比证据。

## 17. 开发顺序和首个交付

| 批次 | 核心交付 | 完成标准 |
|---|---|---|
| 1 自动竞品分析与机会列表 | 事件最小归组、增量任务、文案级多作品对比、带证据的机会列表 | 一轮真实输入自动产生可复核机会；无数据／失败不伪造结论 |
| 2 自动选题卡与标题 | 账号适配、排序、3—5标题、采用／拒绝／修改、版本保存 | 机会→选题→编辑反馈端到端可用 |
| 3 发布关联和复盘 | 关联实际作品、同期结果、修改反馈、评估样本导出 | 不依赖人工Excel也能追踪建议到结果 |
| 4 专用模型训练与替换 | 标注、基线、微调、独立测试、影子／灰度、回退 | 比基础模型与规则有可重复改进，不只训练完成 |
| 5 热点预测与历史日历 | 冻结标签、前瞻预测、30天验证、可核验日期节点 | 预测指标／样本／覆盖公开，日历日期有依据 |
| 6 例外审核自动化 | 各任务按达标范围放权、漂移监控与低成本迭代 | 常规建议主动产出，人工介入量实际下降 |

预测所需快照和标签准备从批次1就开始留存，不等训练阶段才回头补采。历史节点整理可以并行设计，但不拖慢自动选题主链路。

第一批建议先使用当前一个自有账号及其已关联竞品，默认先分析最近7天、以已采集数据为界；可逐步扩到多账号，不硬编码账号名。交付“自动机会列表”，不要先开发大型手动事件管理后台。起初用现有配置模型跑通闭环并建立基线，同时收集真实训练数据，之后训练并替换，而非等待模型训练结束才有产品可用。

下一步具体交付是批次1的实现清单：事件与证据Schema、任务输入输出、接口、最小存储／迁移草案、模型预算与故障矩阵、验收样本及开关策略。自动模型调度和新增存储尚未由本文启用。

## 18. 实施前需最终定稿的事项

1. 首期自有／竞品范围和采集覆盖；是否先采用现有一个自有账号及其关联竞品。
2. 自动分析的运行时段、每日预算、超限优先处理策略；建议先A1自动建议，发布不自动执行。
3. 热点标签的扩散与增长门槛、每日预测截点和可观测性最低要求，正式验收前冻结。
4. 基础模型、可训练许可、可用GPU／显存／存储、训练和推断能否并行。
5. 账号定位、禁用表达、必须审核议题及可使用的外部日期／事实来源。

这些事项影响自动运行配置和预测验收，不妨碍先提交批次1接口与存储设计。训练和扩展采集不因方案完成而自动启动。

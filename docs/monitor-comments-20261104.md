# 监控账号评论与子评论采集

日期：2026-11-04。

## 使用入口

采集设置 → 选择已保存账号 → 展开「评论与子评论采集」→ 勾选自动采集、子评论并单独保存。默认关闭，不因升级扩大已有账号请求量；主评论默认50条/作品，子评论默认合计100条/作品。支持主评论1—200，子评论0—500，服务端和界面校验整数范围。

内容情报阅读区及内容表现作品详情均提供「评论与子评论」折叠区，展开只读本地已保存数据。可按需手动「采集 / 更新评论」，查看评论文本、脱敏昵称、时间、点赞及回复树，主评论与每个回复列表分别20条分页。空状态不等同平台零评论。

## 自动采集与边界

- 保存新作品、首次快照及后续快照任务后，在原浏览器上下文中处理评论，不另起采集浏览器、不触发模型。
- 每次账号发现最多处理3个到期作品，评论阶段总时间预算120秒；每作品最多10次请求，单请求超时30秒，每次请求前等待5秒并检查停止标记。评论正文和子评论分开限量，分页游标不推进或响应不完整不伪装成成功零数据。
- 近7天作品成功采集后至少间隔6小时，在下一轮账号发现时刷新；普通失败至少间隔30分钟，仍遵循账号调度。手动采集同作品至少间隔60秒，不绕过全局暂停、账号停用、浏览器占用、浏览器恢复及风控冷却。
- 发现阶段的部分成功仍保留新作品评论队列。没有新作品的后续发现也处理到期队列。超过7天或已不可用的作品退出自动评论更新，已有记录保留；可对仍有效作品手动采集。
- 评论风控立即停止后续评论请求，并走既有风控处理。不改既有冷却参数。评论失败不回滚已保存作品、快照和任务；部分分页与已有评论保留，重复按作品ID＋评论ID更新，不重复插入、不推断删除。
- 回复挂在请求对应的主评论下；保留原始正文，不补造评论。用户标识仅保留匿名哈希、昵称脱敏，不采集用户主页、头像或IP归属地。评论不是已核实事实。
- 未提供历史作品自动批量补评论、全量评论保证、情感分析、模型评论总结或导出新格式。

## 存储与接口

独立 `database/monitor_comments.db` 存储账号政策、执行状态与评论。初次明确保存政策/采集时创建；读取不存在的存储返回默认值，不自动建库。现有账号、作品、快照及通用爬虫评论表结构不改，无正式库Schema迁移。现有通用采集器评论表未混用，避免保存选项或个人信息字段差异影响监控链路。

新增接口，原账号请求/响应结构不变：

- `GET /api/monitor/accounts/{account_id}/comment-policy`
- `PUT /api/monitor/accounts/{account_id}/comment-policy`
- `GET /api/monitor/posts/{aweme_id}/comments?page=1&parent_comment_id=`
- `POST /api/monitor/posts/{aweme_id}/comments/collect`

执行状态接口的kind增加comments、phase增加comments，界面同步支持。账号发现结果增加comment_collections数组，保留原有字段。

## 当前生效状态与后续

前端已应用。运行中的本地后端OpenAPI尚不包含评论新接口，需要重启后端再操作设置；本轮未停止正常监控、未重启服务。重启后先选择一个账号启用有限评论采集，再观察下一篇新作品的评论保存及实际平台响应。隔离验证不代表真实平台已完成验收。

侧库为追加/更新存储，当前无自动保留期和删除评论功能，长期增长需后续制定归档策略。达到单轮预算、平台隐藏/删除评论及登录权限都可能造成采样不完整。

回滚时先关闭账号评论政策，再撤回本次接口/服务/组件接入，或切回保全的前端资源；保留侧库便于再次恢复。无需回滚现有账号/作品表Schema，不以删除作品或评论库作为默认回滚步骤。

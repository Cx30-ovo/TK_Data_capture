# 选题保存与编辑反馈 v0.1

日期：2026-11-02。本阶段接在标题工作流第 5—8 步之后，仅实现显式保存草稿、编辑选择和版本历史，不接发布、复盘或训练。

## 使用方式

1. 在“同事件竞品对比 → 事件机会池”中生成标题候选。
2. 点击候选的“保存为选题”，创建版本 1，生成原稿保持原值。
3. 展开本页“选题草稿与编辑反馈”，点击“编辑与反馈”。填写编辑后标题、角度、备注，选择“待编辑 / 采用原标题 / 修改后采用 / 不采用”。
4. 修改或拒绝必须填写原因；保存追加新版本，版本历史可查看旧版完整内容。采用只记录标题编辑选择，不代表发布、事实已核实或允许训练。
5. 冲突时保留未提交输入，显示“内容已更新，请刷新后重试”；显式读取当前版本、人工核对后再保存，不自动合并。

保存、反馈和读取均不调用模型，也不重新分析原始材料。未经人工审核的反馈始终标记 `training_eligible=false`。本地当前没有自动导出、自动训练或发布入口。

## 存储与数据边界

- 复用既有 `comparison_automation.db` 的 `automation_document` 文档，在独立 `editorial_drafts` 命名空间下保存草稿与幂等索引。不新增数据库、表、列、索引、约束或迁移，不改采集库。
- 保存时服务端从完成的生成记录查找已保留候选，校验生成请求 SHA 和候选 ID；客户端不能伪造模型原稿、证据或档案绑定，也不能保存已经过滤的候选。
- 原稿快照包含候选及其原文引用、文案/片段 SHA、生成请求身份、机会及账号身份、生成和策略版本、风格档案、材料绑定、模型配置摘要 SHA 及对应写作合同。配置摘要不含可读取的地址或凭据。
- 每次保存记录标题、角度、选择、原因、备注、父版本、内容 SHA、保存时来源状态。旧修订与原稿快照不覆盖。
- 幂等键相同且请求相同，返回原提交对应的版本；同键不同内容返回 409。幂等重放先于并发判断，提交已成功但响应丢失时不会重复新增版本。
- 客户端遇到网络中断或服务器错误，锁定该次提交的输入、正文、版本及幂等键；用户点击“核对原保存请求”才显式重放。没有自动重试。
- 来源直接按保存的作品 ID、账号身份和文案绑定核对，不依赖机会池当前时间窗口，也不因最新风格档案更新而改写旧稿。封面地址轮换不使文案引用失效。
- 来源删除、文案变化、身份变化或原作品库不可用时，草稿及原稿仍可读，显示“来源不可验证”；禁止新建，只允许旧稿追加人工备注，不提升事实有效状态。
- 作品库与控制存储是两个独立数据库，**不宣称跨库原子事务**。保存前及响应时检查来源；若检查后来源又变化，响应或下一次读取会标为不可验证。保存时的来源一致状态不是事实已核实结论。
- 首期安全上限：500 张草稿、每稿 100 个版本；同时受既有控制文档 8 MiB 总上限约束。超限拒绝，事务回滚，不清理旧稿。标题、角度、原因、备注分别最多 1000 个 Unicode 码点，前后端一致，不截断。

底层路径保护补一处边界：原作品库缺失时仍可读取独立控制存储，保留同路径、符号链接及硬链接隔离检查。该调整用于满足“原库不可用但旧稿仍可读”，并非放开对采集库的写入。

## 接口

| 接口 | 行为 |
|---|---|
| `POST /api/monitor/editorial-drafts` | 从已完成、已保留标题候选创建草稿；请求含 generation（原生成请求）、candidate_id、编辑内容及 save_key |
| `GET /api/monitor/editorial-drafts` | 按目标账号分页，参数 owned_account_id、page、page_size |
| `GET /api/monitor/editorial-drafts/{idea_id}` | 读取当前版本、不可变原稿快照和当前来源状态 |
| `POST /api/monitor/editorial-drafts/{idea_id}/revisions` | expected_version、save_key 及完整编辑内容；追加版本 |
| `GET /api/monitor/editorial-drafts/{idea_id}/revisions` | 分页读取完整历史版本内容及 SHA |

编辑内容字段为 title、angle、note、decision、reason。decision 的四个值是编辑反馈，草稿整体 state 始终为 draft。已有标题生成、同事件分析及监控接口结构不变。

## 已知限制与后续

1. 这是单用户本地编辑闭环，没有多人权限/审校流、发布、旧版本恢复入口、导出训练集或训练执行功能。
2. 人工修改后的标题没有自动重新调用模型或语义事实复核；始终 needs_editor_review，不因采用按钮转为“事实通过”。
3. 使用现有共享控制文档，便于不迁移地建立首期闭环，但会共享容量与写锁；扩大到高并发、长期大批量稿件前应另审独立持久化设计与迁移。
4. 初始本地草稿列表为 0；本轮真实环境只验证读取，保存完整流程已在隔离库验证。下一步使用真实选题进行编辑采纳与修改试用，不自动写入验收样稿。
5. 发布复盘应在确认可追溯的选题/标题选择后，再关联实际发布作品，按固定生命周期读取快照；训练闭环最后建设，并保留人工审核、样本拆分与离线评估。当前不能据此宣称训练完成或热点预测达到 70%。

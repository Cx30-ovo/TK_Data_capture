## 1. 文档信息

- 项目：MediaCrawler / 单账号持续采集扩展
- 更新日期：2026-09-14
- 适用平台：当前新增监控能力以抖音为主

## 2. 本次新增功能概览

本次改造在原有一次性爬虫任务基础上，新增了单账号持续监控、互动快照、时间范围筛选、风控重试、浏览器复用和运行日志功能。

主要能力包括：

1. 抖音作品发布时间区间筛选。
2. 风控等待 10 分钟后自动重试。
3. 单账号增量发现新作品。
4. 自动生成 1h、6h、24h、72h、7d 快照任务。
5. 只执行到期快照，不重复抓取全部历史作品。
6. 记录实际观测时间和实际发布后年龄。
7. 错过窗口的历史快照标记为 `missed`，禁止倒填。
8. 复用同一个 Chrome 窗口和稳定标签页。
9. WebUI 新增定时采集和单账号监控面板。
10. 新增 `output` 目录持久化运行日志。
11. 第一次发现新作品时保存 `first_seen` 首次观测快照。

## 3. 抖音时间范围筛选

### 3.1 功能说明

支持按作品发布时间筛选抖音搜索结果、指定作品和创作者主页作品。

- 开始日期和结束日期均包含当天。
- 结束日期按当天 `23:59:59` 处理。
- 留空表示不限制时间。
- 创作者翻页时，一旦遇到早于开始日期的作品，会在处理完当前页后停止翻页。

### 3.2 WebUI

在抖音平台的“目标配置”区域新增：

- 开始日期
- 结束日期

### 3.3 命令行参数

```text
--start_time YYYY-MM-DD
--end_time YYYY-MM-DD
```

### 3.4 配置项

文件：`config/base_config.py`

```python
START_TIME = ""
END_TIME = ""
```

## 4. 风控等待重试

### 4.1 功能说明

抖音详情或创作者翻页遇到风控时，系统可以等待后重试，避免立即失败或重复抓取已经成功的数据。

### 4.2 当前策略

- 作品详情批量抓取失败后，只重试失败作品。
- 创作者列表翻页失败后，等待后重试当前页。
- 默认等待 600 秒。
- 快照任务最多尝试 3 次。
- 超过允许窗口仍无法采集时，快照阶段标记为 `missed`。
- 不使用后续累计互动值倒填历史快照。

### 4.3 配置项

文件：`config/base_config.py`

```python
ENABLE_RISK_CONTROL_RETRY = True
RISK_CONTROL_RETRY_DELAY_SECONDS = 600
```

## 5. 单账号持续监控模块

### 5.1 功能概述

单账号监控模块用于持续跟踪一个抖音账号：

```text
每 30 分钟发现新作品
-> 保存作品基础信息
-> 生成互动快照任务
-> 到期采集互动数据
-> 写入真实快照历史
```

### 5.2 增量发现

- 默认每 30 分钟检查一次。
- 第一次运行只取最新一页建立基线。
- 后续运行遇到已知 `aweme_id` 后停止翻页。
- 不重复抓取全部历史作品。
- 重复运行不会重复插入作品。

### 5.3 快照阶段

第一次发现新作品时立即保存一条 `first_seen` 快照：

- 记录第一次发现时的真实互动数据。
- `captured_at` 为实际发现时间。
- `actual_age_seconds` 为发现时间减去发布时间。
- `first_seen` 不等于 `1h`，不会混用。
- 历史作品不能事后伪造 first_seen，除非明确标记为 baseline。

每个新作品生成五个快照任务：

| 阶段 | 计划时间 | 建议允许窗口 |
|---|---|---|
| 1h | 发布后 1 小时 | 30 分钟 |
| 6h | 发布后 6 小时 | 2 小时 |
| 24h | 发布后 24 小时 | 6 小时 |
| 72h | 发布后 72 小时 | 12 小时 |
| 7d | 发布后 7 天 | 24 小时 |

每个快照记录：

- 计划时间 `due_at`
- 实际观测时间 `captured_at`
- 实际发布后年龄 `actual_age_seconds`
- 点赞、收藏、评论、转发数

### 5.4 错过历史快照

如果开始监控时作品已经错过某个阶段：

- 对应任务标记为 `missed`
- 不执行迟到采集
- 不用后来的累计值倒填旧阶段

例如：第一次监控时发现一篇两天前的作品，则其 1h、6h、24h 任务会按窗口规则标记为 `missed`，72h 和 7d 仍可继续执行。

### 5.5 后台循环

后端启动后自动运行：

- 每 60 秒检查一次到期快照。
- 根据账号间隔检查是否需要发现新作品。
- 普通爬虫任务运行中时，监控循环跳过本轮，避免浏览器冲突。

## 6. 数据表

已有五张监控相关表。

### 6.1 douyin_monitored_accounts

保存监控账号：

- `platform`
- `sec_user_id`
- `profile_url`
- `enabled`
- `discover_interval_minutes`
- `last_discovered_at`

唯一约束：`UNIQUE(platform, sec_user_id)`

### 6.2 douyin_posts

保存作品基础信息：

- `platform`
- `aweme_id`
- `sec_user_id`
- `title`
- `desc`
- `create_time`
- `first_seen_at`
- `canonical_url`
- `status`

唯一约束：`UNIQUE(platform, aweme_id)`

### 6.3 douyin_post_snapshots

保存实际互动快照：

- `stage`
- `due_at`
- `captured_at`
- `actual_age_seconds`
- 点赞、收藏、评论、转发数

唯一约束：`UNIQUE(platform, aweme_id, stage)`

### 6.4 douyin_monitor_jobs

保存任务和状态：

- `job_type`
- `dedupe_key`
- `aweme_id`
- `stage`
- `due_at`
- `status`
- `attempts`
- `last_error`
- `miss_reason`

状态值：

```text
pending / running / done / failed / missed / skipped
```

### 6.5 douyin_topic_profiles

## 7. 后端服务与接口

### 7.1 监控服务

文件：`api/services/monitor_service.py`

主要方法：

- `discover_account()`：发现并保存新作品。
- `run_due_snapshots()`：执行到期快照任务。
- `_loop()`：后台循环。

### 7.2 监控接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/monitor/status` | 查询监控状态、任务统计 |
| POST | `/api/monitor/config` | 保存监控账号配置 |
| POST | `/api/monitor/discover` | 手动执行一次发现 |
| POST | `/api/monitor/snapshots/run-due` | 手动执行到期快照 |

保存监控账号示例：

```powershell
Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8080/api/monitor/config `
  -ContentType 'application/json' `
  -Body '{"sec_user_id":"MS4wLjABAAAA...","profile_url":"https://www.douyin.com/user/MS4wLjABAAAA...","enabled":true,"discover_interval_minutes":30}'
```

## 9. 浏览器复用

### 9.1 目标

避免每次任务都新建浏览器窗口或标签页。

### 9.2 当前策略

- 固定标签页标识为 `MediaCrawler`。
- 优先复用已记录的有效 CDP 端口。
- 记录失效时自动扫描 `9222` 到 `9331` 范围内的有效端口。
- 程序专用 Chrome 不再在任务结束时强制关闭。
- 后续任务复用同一个浏览器进程和同一个标签页。

### 9.3 配置项

文件：`config/base_config.py`

```python
CDP_CONNECT_EXISTING = False
AUTO_CLOSE_BROWSER = False
```

## 10. 运行日志

新增目录：`output/`

日志文件：

- `output/crawler.log`：Python 爬虫日志
- `output/webui.log`：WebUI 控制台、调度器和监控循环日志

日志策略：

- 单文件最大 10 MB
- 自动轮转，保留 5 个历史文件
- 日志文件被 git 忽略
- 无写权限时自动降级为仅控制台输出

监控循环新增日志示例：

```text
[Monitor] Discovering new posts...
[Monitor] Discovery result: fetched=..., new_posts=..., new_jobs=...
[Monitor] Running N due snapshot jobs

```

## 13. 已知限制

1. 首次监控只建立最新页基线，不自动回填全部历史作品。
2. 监控开始时已经错过的历史快照会显示为 `missed`，这是预期行为。
3. 定时和监控循环只在后端服务运行时执行。
4. 需要项目专用 Chrome 保持登录状态。
5. 月度选题分析表和结构已建立，但分析逻辑尚未实现。
6. 当前监控模块只支持单账号。

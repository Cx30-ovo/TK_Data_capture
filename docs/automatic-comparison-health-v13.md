# 后台运行健康看板 v13

已在本地应用。范围为同事件竞品对比的增量发现/自动分析后台，不代表全站采集、调度和平台连通性总健康。

## 展示

- 常驻紧凑概览：进程心跳、发现状态、分析状态、最近成功扫描、下次扫描预计时间、今日自动预算预留。
- 账号关系扫描明细默认折叠：窗口作品数量、新增、内容变更、候选检查、入队、复用、去重和原因。
- 区分首次基线、没有新增/变更、未匹配、去重、复用、扫描异常；失败不推进成功游标，失败本次统计为空。
- 区分发现关闭、分析关闭、模型关闭、预算耗尽、连续失败冷却和候选等待重试。预算是请求预留，不是实际成功请求数量；全局批次互斥和共享预算仍受原执行器控制，具体拒绝见候选错误。
- 无心跳证据、停止和超过90秒未更新不显示在线。状态查询失败时明确提示为上次读取结果。

## 实现文件

1. api/services/comparison_automation_service.py：进程内15秒心跳、扫描统计、只读健康投影和预计扫描时间。保留原匹配、模型预算和执行规则。
2. webui/src/lib/automaticComparison.ts：向后兼容新增健康与扫描统计类型。
3. webui/src/components/monitor/ComparisonAutomation.tsx：常驻健康概览和折叠扫描明细。
4. tests/test_comparison_health.py：隔离健康定向测试。
5. tools/accept_model_comparison.py：健康看板浏览器验收和限定旧状态文本选择器，避免新增概览带来的定位歧义。

无新表、迁移、采集数据修改或模拟作品写入正式库。统计随既有自动控制文档保存；历史文档缺字段显示暂无统计，等待下一次成功扫描。

## 边界与后续

心跳是当前API进程的后台任务观测，未聚合多进程健康；部署仍按现有单进程方式。在线表示工作线程有新鲜心跳，不保证扫描、模型或采集平台成功。预计时间受60秒后台轮询、耗时任务、错误和互斥影响，不承诺精确触发。每组统计为最近一次扫描，不是全局去重作品总量；快照变化可产生新候选材料，但不计为新发布作品。首次基线不补跑历史作品。

还未以真实新增作品证明持续多日稳定性；接下来观察一条真实新作品从扫描、匹配、入队到存储分析的完整链路。测试没有调用真实模型；恢复的原有自动开关继续按用户配置正常运行。

## 回滚

前端可从本轮完整保全副本恢复index与对应资源；保留其他旧资产。后端按本轮文件改动逆向恢复并安全重启，无SQL回滚。新增JSON统计字段可被旧读取逻辑忽略；不要覆盖用户已有配置或队列文档。

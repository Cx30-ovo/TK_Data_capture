# 采集吞吐优化

- 账号发现沿用已知非置顶作品停止条件和发布时间边界；补封面模式继续扫描，不受普通增量边界影响。
- 同轮分页按作品 ID 去重；平台重复返回整页或游标循环时停止继续请求，保留已取得作品。
- 定时循环每轮先处理最多 10 个快照，再执行到期账号发现，最后续采一条评论任务。手动快照批次默认仍为 50。
- 定时发现和定时快照只将评论写入待采队列，不在其浏览器锁内同步采评论。手动操作保留原有采评论行为；快照评论刷新仍会入队，后续周期继续处理。
- 快照阶段任务的已存在键一次查询，替代每阶段单独查询；单批重复阶段同样去重，保留数据库唯一约束。
- AI 文字复核和视觉复核保持独立后台队列，不在作品发现和落库路径调用模型。新增测试防止采集路径误接 AI 等待。
- 发现结果新增 elapsed_seconds、new_posts_per_minute、comments_deferred，供对比成功入库速率。速率包含本次连接、请求、入库及附带操作耗时；非请求并发量。

不调整平台请求间隔或增加浏览器并发。仍遵守现有浏览器互斥、暂停、重试与风控冷却。
本次离线测试不能证明真实平台速率提升，需在后端加载新代码后对比相同账号和相近作品量的发现结果。

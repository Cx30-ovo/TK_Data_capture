# 评论区紧凑展示与快照同步更新

日期：2026-11-04。

## 使用效果

- 评论区默认折叠；展开后，评论列表最多为12rem或视口高度的28%（取较小值），多评论只在列表内滚动。展开子评论、长评论全文也不增加该上限，保留主评论和回复各自的分页。
- 长评论默认两行，仅在实际溢出时显示“展开全文”，可再收起；正文原值不截断、不修改。正文长词可换行，列表可通过键盘聚焦和滚动。
- 缩短日期和行间距，采集状态压为一行，详细采集说明默认折叠，避免数量、状态、说明反复占据纵向空间。完整时间保留在提示中，空状态及失败提示继续显示。

## 快照联动

- 对已启用账号评论采集的作品，快照提交成功后登记评论更新，在同一快照批次的原采集会话内执行；优先保存本批快照，再更新评论。相同账号和作品的多个成功快照在一个批次中合并一次评论更新。
- 新快照可提前触发评论刷新，不必等待普通六小时刷新周期；每作品最短间隔、错误重试间隔、全局暂停与风控冷却继续生效。账号/评论采集关闭、快照暂停或快照采集失败时不新增评论请求。
- 评论已有分页进度时先继续原游标，不直接重置。既有payload中保存刷新代次；原遍历完成后若仍有更新请求，下一时间片从主评论首页再检查最新评论，不丢失中途收到的快照更新。
- 全部成功快照先登记待更新队列。达到时间片预算、安全停止或遇到风控时，未执行的评论保留待续采；评论风控立即停止后续评论请求并走既有冷却处理。
- 评论失败独立登记，不撤销已成功保存的快照，不把成功快照重新标为重试。快照执行结果仅在存在评论更新时增加可选comment_collections字段；没有评论跟进时保持既有返回结构。
- 不增加表、列、索引或迁移，不调用模型。采集数量仍无上限，平台隐藏、删除或权限受限的评论不可取得。

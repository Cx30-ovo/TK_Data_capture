# 自动选题与本机训练准备 v0.1

日期：2026-11-02。当前开发方向改为先补齐自动选题与训练准备，暂不建设采用后的发布关联和效果跟踪。本机训练已确认，显卡、显存与基础权重待后续核对。本轮没有启动实际训练。

## 已实现范围

现有新增发现／自动竞品分析 → 机会池 → 增量选题任务 → 复用事实提炼与角度规划、标题生成与复核 → 自动保存待编辑草稿 → 编辑反馈及样本审计。

自动选题有独立开关，**默认关闭**，不随原自动竞品分析开关开启。作用于全部已启用的自有—竞品关系；界面执行记录按当前自有账号过滤，设置注明为全局策略。GET、页面轮询和训练审计不调用模型。

首次默认只建立现有线索基线，后续处理新增／变化线索。若需处理已有线索，可在首次开启时明确勾选“首次扫描也处理现有线索”；该选项在初始化和切换选题范围重新建基线时生效。任务失败、来源变化和结果未确认均不无限重试；内容校验失败不生成模板替代。

保留每日标题请求不限次的既有规则。新自动任务默认每轮最多策划 1 条，可设 1—5；扫描间隔默认 300 秒，worker 每 60 秒检查。每条复用已有最多两阶段、各最多 3000 输出 token 的标题链路，不额外增加选题模型调用。暂停阻止下一阶段和后续入稿，已发送请求可能完成，无法撤销已完成草稿。

任务具有持久化去重键、输入指纹、执行租约和状态。相同材料不重复生成；生成中断标“结果未确认”并禁止自动重发；已完成生成但入稿中断可用原记录及原幂等键继续保存，不重复请求模型或重复建稿。来源失效时不生成新草稿，部分已保存草稿保留。

每个保留候选分别保存为待编辑草稿，原稿、引用、账号风格版本、标题管线版本及 SHA 保留。**不会自动采用、发布或转为训练合格样本。** 不足 3 个候选如实保存实际数量，零候选标“材料不足”。缺少风格档案时拒绝相应任务，不自动更新档案或取消风格要求。

机会筛选沿用现有事实差异、后续进展等规则优先级；不是训练后的推荐模型。疑似已覆盖线索不直接生成。覆盖待查仍明确为检索线索，不升级为“自有未报道”。同一目标账号／竞品作品选最高现有规则优先级线索，未实现跨作品语义事件聚合。界面持续标注事实待核实。

## 训练准备

在当前账号下审计草稿总量、编辑反馈和不可验证来源。显式确认后导出唯一新目录，包含 `review-samples.jsonl` 与 `manifest.json`，记录原稿、最新编辑内容、引用、样本来源类别、内容 SHA、生成版本及数据集 SHA。Windows 下按 UTF-8 原字节写 JSONL，清单 SHA 与实际文件一致。

导出不修改数据库、不调用模型、不启动训练。来源不可验证的样本排除并登记；模型输出、编辑采用、修改和拒绝分别保留语义，拒绝不自动当作负例。全部样本 `pending_review`、`training_eligible=false`。现有草稿也不因新增功能被批量提升核验状态。

同作品及共享引用链采用连通分组，按整组最后时间生成训练／验证／测试切分建议；少于 5 个引用组不切分，标 `unassigned`。**这不能穷尽同事件不同作品、转载链及语义重复，切分仍需事件审核后冻结。** 不将建议切分宣称为已封存独立测试集。

本期语料范围是已保存草稿及其标题来源，不是全量账号历史作品训练集。实际训练前还需：核对本机 GPU／显存、可微调基础权重及 tokenizer、数据使用范围、人工标签；导入适合的历史作品，清洗去重并冻结评估集；选择 LoRA／QLoRA 参数并做离线基线对照。现有模型服务 API 不是可直接微调权重的证明。未实现热点结果标签，因此不能据此开始或宣称达到 70% 热点预测命中率。

## 接口与存储

- `GET /api/monitor/idea-automation`：只读状态与分页，可选 `owned_account_id` 过滤任务。
- `PUT /api/monitor/idea-automation`：显式保存全局策略，校验 `expected_version`，冲突返回 409；不直接执行模型。
- `GET /api/monitor/training-data/readiness`：只读审计，要求目标账号。
- `POST /api/monitor/training-data/exports`：显式确认后导出待审核语料；不写业务数据库。

复用现有控制文档的 `idea_automation` 命名空间、现有标题生成与草稿存储，不新增表／列／索引，不执行迁移。不改变采集、匹配、风控冷却或原自动竞品分析逻辑。扫描最多 500 条线索、队列最多 500 任务、seen 最多 5000 项，仍受现有共享文档 8 MiB 上限约束；达到容量明确报错，不静默截断或删除旧证据。

# 保存选题后的直达编辑优化

日期：2026-11-02。

截图中的“已保存为选题”表示保存已成功。本轮处理的是保存后的操作衔接：候选旁增加“编辑此选题”，直接展开本页草稿区、读取对应草稿、定位并聚焦编辑器；成功提示缩短为“草稿已保存 · 尚未发布”。不改变保存接口、原稿绑定或版本规则。

## 变更范围

| 文件 | 用途 |
|---|---|
| `webui/src/components/monitor/EditorialDrafts.tsx` | 增加候选直达入口和组件内打开方法；编辑器独立于分页列表渲染；处理加载、失败重试、焦点返回及已有编辑内容保护 |
| `webui/src/components/monitor/EventOpportunityPool.tsx` | 用组件 ref 将候选入口连接到当前账号的草稿区，不使用全局事件 |
| `tools/accept_model_comparison.py` | 扩展原隔离浏览器测试并增加另一草稿正在编辑时的保护测试 |

另有本文档、独立构建及本轮证据。此表列出本任务范围，不表示已有工作区只有这些变化。后端、API 契约、数据库结构均未修改。

## 交互规则

1. 保存成功后由用户点击“编辑此选题”，不会强制中断候选阅读。
2. 使用保存响应中的真实草稿 ID，打开时只调用已有读取接口，不再次创建草稿或调用模型。
3. 草稿区关闭或对应条目不在当前列表页时仍可打开；读取失败保留入口供显式重试。
4. 同一草稿已打开时只定位，不重载、不清空未提交输入。另一草稿已打开时提示先收起，定位当前编辑器，不请求另一草稿、不自动替换。
5. 收起或 Esc 返回实际触发按钮；原按钮已离开页面时回到草稿区标题。版本保存、409、来源降级与不确定响应处理沿用原逻辑。

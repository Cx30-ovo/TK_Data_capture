# 账号档案增量分析 v0.5

## 执行边界

监控仅采集作品。GET 仅读取材料并派生待分析队列，不写库、不调用模型。
POST 由编辑主动触发，模型关闭时拒绝；不新增自动模型调度任务。
建议更新门槛为实际新增或文案修改达到30篇，或输入有变化且距上次更新满24小时。
按当前完整可用材料SHA与最新快照比较，不把同批被动重算作品计入30篇门槛；
移出窗口也不计入新增/修改数量，但仍参与输入变化和24小时规则。
changed_posts表示实际新增/修改数，pending_posts仍表示实际需要重算的样本数，两者口径独立。
每30天重新从原始材料校准，不递归用旧摘要代替原文。

## 缓存与队列

沿用 ai_analysis_results 追加式快照，不建表、不迁移、不改旧记录。
保存逐篇成员（作品ID、完整清理文案、文案SHA、发布时间）、批次输入SHA和已校验结构化分析。
绑定账号身份、模型及服务配置摘要、提取版本、提示词、分析版本、上下文预算。
仅当批次所有成员与当前样本完全一致时复用批次分析；单篇变化或移出窗口会使所属批次重算。
这是逐篇身份校验、批次级语义缓存，不宣称已有独立逐篇风格推断。
队列由当前输入和最近50份历史快照派生，重启后可重建，不新建暂存库。
原因包括 new、changed、batch_invalidated、reanchor。
采样仍为最近最多5000篇内等距抽样500篇；样本重新分布可能使多个批次失效，不能保证每次仅处理新增作品。
批次碎片超过12批时重做当前原文样本，而不是无限增加摘要长度。

## 窗口与统计

近期窗口沿用页面天数；长期为365天，两者独立快照和分母。
两者均有500篇样本上限，长期不代表全部历史。
主题归属来自模型，当前样本计数和占比由代码重算，移出的作品不进入当前分母。
每次汇总重新组合当前有效批次，所有引用仍定位原文，不继承旧汇总结论。

## 预算和失败

POST 可选 max_model_requests，默认13，范围1—13。
请求前检查新批次数+1次汇总是否超过预算，超过则422且零请求。
输出预算为每请求至多3000 token（还受模型配置限制），13次至多39000输出token，不是费用承诺。
串行调用，无自动重试；任一步失败不保存新快照，原档案保留。
分析结束再核对输入和身份，变化则409拒绝保存。
所有新批和汇总成功后一次追加快照，因此失败重试可能重新调用尚未提交的新批。

## 界面

集中显示待分析/复用数量、预计请求数、建议更新原因，提供观察范围和本次请求预算选择。
默认手动更新，没有偷偷启用自动推断；未来若需定时模型执行，另做开关、持久任务和每日预算设计。

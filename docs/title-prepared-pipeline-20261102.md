# 标题工作流第 5—8 步实现与同组真实材料重验

日期：2026-11-02。最终本地后端版本：`opportunity-titles-v0.9.1`。本次只完善独立事实、角度规划、账号风格写作和复核，不实现选题保存、编辑反馈、发布复盘或模型训练。

## 1. 实现结果

1. **先事实与角度，再写标题。** 一次页面操作最多顺序请求模型两次。第一阶段仅输出事实与计划，先校验引用、事实归并和计划关联；失败立即停止。第二阶段只能返回标题、自查和限制，不能改写已冻结的事实与计划。材料不足可以只完成第一阶段、返回零候选，不补模板。
2. **生成前建立来源绑定的写作清单。** 服务端按每个计划形成原文片段、主体/动作/对象说明及必留要素，包括金额单位与角色、比例指标、案件/地点范围、返还关系、来源链、限定与过去表态日期。使用全部相关主事实片段生成约束，不由写作模型挑一个日期片段来规避。
3. **日期明确且不冒充新进展。** 清单提供来源允许的完整月日格式；只写“28日/29日”不能替代月日。明确发言日期前的逗号可识别，但纯事件日期不会自动变成发言日期；没有可定位的发言日期就不伪造。旧计划即使删掉“将”也继续受准备阶段的时间约束。
4. **写作仍使用最新已保存账号档案。** 不因作品增量或时间窗口变化让档案过期，不自动更新档案；每条标题提供实际引用的风格特征及标题片段。风格不提供事实或时效授权。
5. **复核结果分层展示。** “生成前必留清单”和“必留要素核对”默认折叠；区分“原词已匹配”“缺失或不一致”“待编辑核对”。原词匹配不代表语义或真实性通过，主体/动作/对象的语义核验仍明确待人工复核。
6. **有界调用与最小诊断。** 每阶段保留既有配置约束，输出最多 3000 token、请求超时配置不超过 90 秒；两阶段合计最大输出预算为 6000 token，实际 token 未查询供应侧统计。页面等待上限改为 210 秒，在途状态保护为 300 秒。不自动重试，不恢复每日标题请求次数上限。阶段事件记录实际尝试次数、校验截点和准备内容 SHA；重复事实诊断仅增加事实/片段 ID、签名 SHA 与相似度，不保存原始推理过程、模型配置或凭据。

第一轮真实材料发现的补充修正：给日期约束增加明确允许写法；识别“据央视援引日本方面消息”这类无“报道”后缀的转引链；明确主体/动作/对象说明允许忠实概括，避免模型自查要求照抄全部器物专名或背景。

## 6. 未决问题与下一步

1. 来源署源异常不自动修正；英国援助材料需人工核实后才能进入可采用内容。模型输出零候选是允许结果。
2. 词法检查不能穷尽语义关系、条件、时间和同义重复。文物返还放在标签内仍可能通过词法检查，正文表达需编辑确认；旧条件警告的时间提示仍可加强。
3. 本轮没有本地民生办理/服务型真实材料，不能据此宣称所有角度已验收；后续应补充独立服务型材料，单列结果。
4. 两阶段带来额外时延与模型消耗；实际 token 成本未采集，无每日次数上限不等于无限上下文或无限超时。
5. 尚未形成专用训练模型、发布效果复盘或热点预测的 70% 命中率证据。本次不建立这些能力的结论。

下一阶段先接**选题保存与编辑反馈**：保留候选原文、采纳/修改/拒绝、修改后标题与原因，并绑定源材料 SHA、规则版本、账号档案及请求身份；不得覆盖生成原稿，也不直接把未经审核的反馈作为训练真值。存储方案确认后再实施。随后再接发布作品关联、固定生命周期效果与快照复盘，最后在可追溯、可拆分评估的数据集上建设训练闭环。

# 多账号监控调度优化

本地变更，未部署到 Mac mini。没有数据库迁移或 schema 改动。

## 调度策略

- 账号发现：每个监控循环只处理一个到期账号。先选到期最久的账号；到期时间相同则按轮转游标选择，避免账号 ID 固定靠前的账号连续占用。
- 快照：每轮最多取3项；SQL使用窗口排名按账号交错排列，并优先到期较早的任务。
- 评论：每轮续采一个作品时间片；可执行账号间轮转，每个账号内部仍按最早到期任务执行。失败、暂停、风控策略及已有退避不改变。
- 话题：通过同一个FIFO调度器排队；每个时间片最多4个搜索页或45秒，单请求最多30秒，整个采集段最多120秒。现有JSON任务配置保存关键词分页游标，下一轮65秒后继续；补采任务仍有原有安全页数边界。
- 快照、发现、评论、话题的自动操作都使用同一调度门闩。普通手动操作仍遵循已有监控锁与暂停策略。

## 逐账号健康

`GET /api/monitor/health?all_accounts=true`增加`account_workload`只读摘要：账号发现时间与逾期、快照待办/积压、评论待办/积压与最久等待、重试剩余、最近错误；同时提供话题待办/补采数量和本轮时间片策略。不会返回账号安全标识，不初始化或写入存储。

健康页增加响应式账号负载列表；为每个账号显示启用状态、发现周期、最近/下次发现、逾期、快照和评论积压、最久评论等待及最近错误。

## 边界与容量

多个账号继续共用一个登录会话和浏览器标签，串行分配时间片，不会并行提高平台请求速率。容量取决于账号数量、发现间隔、每页耗时、快照积压和话题关键词数。账号数量超过单浏览器服务速率时，逾期指标会如实增长；不自动增加请求频率或绕过平台冷却。

当前调度公平性在单个服务进程内有效。多个服务副本若同时连接同一数据源，仍需共享的分布式调度租约；本实现不声称支持多副本并发采集。

## 验收

定向测试覆盖发现年龄/轮转、跨账号评论轮转、FIFO执行、话题游标跨时间片续接、逐账号健康摘要。完整监控回归和独立Vite构建结果记录在`tmp/multi-account-optimization-20261117-01/`。

# 账号矩阵 v0.1

## 页面与业务范围

独立业务导航 `?tab=accounts`；系统设置保留账号增删、监控开关、频率、调度和维护，矩阵保留业务身份、分组、竞品关系与档案入口。未重构采集业务，也不在矩阵保存时自动触发采集。

账号默认待分类，由用户选择自有/竞品；单个自由文本分组（Unicode 码点最多 50）；每个自有账号可关联最多 100 个已分类竞品。关联不是同事件分析结果。修改被关联的竞品身份必须先显式移除关系。

## 存储与接口

- `GET /api/monitor/account-matrix`：读取全部监控账号、有效作品数量、最近发布时间、有截止前观测的作品数量、业务元数据、全局版本和限制说明。
- `PUT /api/monitor/account-matrix/{account_id}`：`expected_version`、`identity_sha256`、`role`、`group`、`competitor_ids`；成功返回最新矩阵；过期版本或身份变化返回 409，非法关系 422，账号不存在 404，不可用 503。
- 使用现有采集数据库的只读连接；不改旧表、不迁移旧表、不更新采集状态。
- 独立 `account_matrix.db` 位于配置的采集库同目录。GET 在其不存在时返回默认，不创建文件；用户第一次显式保存时创建独立元数据库及 `matrix_document` 单行文档表，后续保存事务内更新。
- 全局乐观版本避免多账号关系交叉覆盖；并发冲突保留当前表单，用户取消后可重新读取，不自动重试或合并。
- 账号业务身份与关联目标均绑定 ID、平台和采集身份 SHA；账号删除/ID 复用不自动继承原分类；失效关联提示人工确认。
- 元数据库损坏不静默回退覆盖；备份时需同时保全采集库与元数据库。当前单机单用户场景，不提供多租户认证或权限隔离。

## 数据边界

作品统计仅包含截止前已发现、已发布、active 的本地作品，不代表平台全量。有观测数量只说明记录存在，不等同生命周期有效覆盖；需在档案查看窗口覆盖与统计口径。无自动风格推断、模型调用、预测或同事件匹配。

## 验证和运行

后端使用测试库验证，只读数据库字节保护；浏览器用 SQLite 备份副本与独立测试元数据库，不启动普通应用生命周期。外围 API 为静态替身，不宣称已有业务全量回归通过。

构建显式输出独立 `webui/dist-account-matrix-*`，不改 Vite 全局配置、不重建 `api/webui`。本轮未启动正式应用，也未创建正式 `account_matrix.db`；用户运行应用并保存后方产生元数据。

## 回滚

只逆向恢复本功能文件变更，保留其他未提交开发成果，不全局 Git 重置。保留独立元数据库作为业务数据备份；旧版不读取它，不需要对采集库回滚。

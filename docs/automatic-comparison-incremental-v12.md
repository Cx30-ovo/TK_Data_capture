# 新增作品候选发现与受控自动分析 v0.1

## 实现范围

- `api/services/comparison_automation_store.py`：独立 SQLite 文档存储，SHA 校验、事务、队列数量和字节安全上限。GET 及默认关闭的后台轮询不创建文件。
- `api/services/comparison_automation_service.py`：账号关系基线、增量扫描、输入指纹、候选版本、历史结果复用、单轮单对执行、租约、预算、冷却及有限重试。
- `api/services/automatic_comparison_service.py`：内部支持精确选择冻结候选，并在开始批次及发请求前重新检查自动授权。公开手动 StartRequest 不变；旧手动请求 SHA 规则不变。
- `api/routers/monitor.py`：新增 `GET /api/monitor/event-comparison/automation?page=1` 与 `PUT /api/monitor/event-comparison/automation`。
- `api/main.py`：随应用启动、停止轻量后台工作循环。
- `webui/src/lib/automaticComparison.ts`：自动配置、队列状态类型及客户端。
- `webui/src/components/monitor/ComparisonAutomation.tsx`：自动设置、预算、冷却、状态计数、基线错误与分页队列。
- `webui/src/components/monitor/AutomaticComparison.tsx`：接入自动设置区，最新已对比记录每 15 秒只读更新；手选历史或手动条件操作后不被自动覆盖。
- `tests/test_comparison_automation.py`：32 项定向断言。
- `tools/accept_model_comparison.py`：新增隔离控制区验收，新增 PUT 白名单仅用于隔离测试库。

## 行为与数据边界

两个开关默认关闭；首次显式保存设置后才创建采集库同目录的 `comparison_automation.db`。只新增独立元数据文档表，不修改采集库表、采集逻辑、账号模型或匹配门槛。既有分析任务和候选冻结包仍使用原独立存储。

后台每 60 秒检查已提交的本地数据；每组关系默认 300 秒扫描一次，范围为全部启用的自有账号及其启用竞品。首次看到关系只建立窗口内作品基线，不回填旧作品。此后新增、补录或文案/封面地址变化发现候选；已进入队列的作品对会检查快照和缓存封面识别变化，形成新输入版本。改变窗口重新建基线，旧待执行条目标失效，不暗中扩大回填。

候选输入 key 包含双方账号/作品/材料 SHA、有效生命周期、缓存封面识别、模型配置及提示版本。下载图片的时钟不作为去重字段，不在发现阶段下载图片。同地址远端图片内容自行改变且本地材料未变的情况不会主动轮询识别。

已有完整匹配输入的手动或自动成功分析复用原 job，不再次调用模型；候选入队和准备执行前均检查复用。新材料版本保留旧结果，不覆盖。候选只由既有字面重合规则召回，不等于同事件判断或全量召回。

只开启发现时积累待分析候选，不发模型或图片请求。开启自动分析后，每次后台循环最多一对，复用既有图片加载、输入验证和模型推断链路。单对输出上限仍为既有 4000 token，图片/文案上下文安全预算沿用。请求前再次检查授权开关、窗口、角色、材料和模型配置。

并发保护：每个来源进程内单飞锁、独立控制文档租约、既有分析任务全局排他共同保护。租约默认 300 秒；超过租约的工作在后续授权检查中拒绝继续。网络最长超时仍沿用原有上限。服务异常退出后的 running 候选标“结果不明”，不会自动重放，也不自动猜测成功；可查看已保存任务。

自动每日默认最多预留 5 次，可配 1—50；与手动共用既有每日总预留上限 50。预留可能多于实际调用，页面明确标预留而非已调用。已知前置拒绝且未建立任务时退还自动预留，不退还已创建任务的全局预留。按 Asia/Shanghai 日界计数，不在内存重置预算。

每份候选默认最多 2 次请求，可改成 1 次。失败默认冷却 3600 秒；连续 3 次失败进入全局冷却，成功清零失败计数。429 保持待执行且冷却，材料/配置/角色失效不盲目重试。关闭开关不取消已发出的请求，但后续请求必须重新通过开关检查。模型总开关关闭时只积累候选。

## 接口契约

GET：只读，未初始化返回 version=0、两个开关关闭和空队列；返回全局配置、状态计数、错误、各关系基线和每页 20 个候选，包含 total/page/page_size。不会触发扫描、迁移、模型或图片加载。

PUT：完整设置文档，包括 expected_version、discovery_enabled、analysis_enabled、days(1—30)、scan_interval_seconds(60—86400)、daily_limit(1—50)、cooldown_seconds(300—86400)、max_attempts(1—2)。严格字段验证，拒绝未知字段和类型转换；分析开关依赖发现开关。并发版本冲突返回 409，不覆盖他人设置。保存本身不调用模型，后台下一轮应用。

既有手动批次的接口和前端入口继续保留，不自动替用户开启开关。列表最新已对比记录仍默认折叠。页面规则文案已区分手动不重试与后台有限重试。

## 已知限制与下一步

- 轮询已提交本地作品，不直接订阅事务事件；发现延迟受扫描间隔影响。首次窗口外/未来发布时间的作品不在本轮范围，停用期间不保证保留窗口外历史。
- 每次最多 20 组关系、每组每轮最多 100 个待检查增量配对，仍受原 500 篇/账号、20000 次配对及文案长度安全上限。超限明确记录，不静默截断或推进游标。
- 队列最多 2000 条、文档 8MiB，旧任务存储仍保留原 500 批上限；不自动删除历史证据，达到上限需另行处理保留策略。
- 不含全量语义召回、模型训练、热度预测、自动发布或事实确证。自动记录不自动进入训练集。
- 当前真实自动分析尚未启用。建议先仅开启新增发现，确认队列与基线，再按预算开启自动模型分析；在模型质量未验证前维持较低每日预算。

回滚：先关闭发现与自动分析，等待在途请求结束；恢复本轮源码保全及前端入口/资源后重启后端。不删除独立队列、旧分析或采集数据，不做全局 Git 恢复。

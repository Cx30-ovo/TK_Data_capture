# 2026-11-06 release

This release aligns comment reading with Douyin: replies are flat under their
root comment, with explicit reply targets beside author names. Reply counts
and tree/list switching are removed from the interface. Existing and newly
collected replies share the same renderer; absent targets remain blank.

Platform-provided reply relationships and masked reply-user identities are
preserved in existing comment payloads. Refreshes retain previously known
relationships when the platform omits them. No new database schema is needed.

Content classification gains clearer category rules, optional human corrections
with conflict checks, and retrieval of current correction examples. Where text
is insufficient, the configured visual model can use sampled video frames or a
separately identified cover fallback. Missing media does not imply video review.

The interface also includes compact reading layouts and evidence presentation.
Release validation uses isolated data and mocked platform/model responses.
Production checks verify service, assets, source identity and data preservation;
they do not certify live collection or model output quality.

Deployment preserves machine configuration, databases, browser login state and
the existing three-hour risk-control cooldown ceiling. The frontend is built
to a unique independent directory before deployment. Credentials, databases,
browser state, temporary evidence and generated builds are excluded from Git.

# 标题过滤诊断与针对性修复

日期：2026-10-29。已应用本地 `opportunity-titles-v0.6.2`，阶段版本 `title-editorial-pipeline-v0.4`。

## 定位与修复

真实诊断不再只保留笼统原因码：新增至多5条候选的标题原文、具体规则、字段路径、缺失限定及允许表达；不记录模型配置、认证信息或完整原始模型响应。历史记录不重写，旧响应缺新字段时兼容显示。

- 飞机事故真实输出“据新华社援引菲媒报道，菲空军证实……”仅因旧规则全局禁用“证实”被过滤，确认误判。
- 财富榜真实输出省略“界面新闻”来源；“二登首富”不属于已批准等价表达。继续过滤，不放松来源或序数规则。
- 引用已剔除重复计划的候选标记 `omitted_plan`，与不存在的 `unknown_plan`、计划字段不一致分开。

修复后仅在原文明示确认主体且标题确认主体一致时允许“证实”，允许保留或省略确认日期；原文“未证实／尚未证实”等不放行，没有确认主体的“已证实”也不放行。该规则是窄范围来源措辞匹配，不是语义事实核验。

模型输入逐片段增加服务端限定规则及允许表达；提示逐条保留来源链和“第二次”，一个计划只写一条候选，事实不足允许0—5条。没有拼接模板、自动改写失败候选或重试循环。

- `tests/test_title_editorial_pipeline.py`、`tests/test_title_candidate_quality.py`：计划差异、来源缺失、重复计划、数字、确认主体、否定及日期用例。
- `tools/accept_model_comparison.py`：新增浏览器诊断可见断言，修正旧预算测试描述。

无新增表、迁移或依赖，不改采集、匹配、分组；没有重置调用计数或删除旧标题。

## 真实验证与过程限制

诊断第一轮沙箱内两次模型请求立即失败，原因封装为通用请求错误；未据此推断模型内容问题。获环境权限后两个诊断请求成功，定位上述原因。两次风格请求因档案失效返回409，均未调用模型。滚动窗口移出材料后更新厦门广电档案52，6次请求、500篇样本，更新截点绑定有效。

首轮最终重验财富榜保留2条、文物保留1条；飞机事故仍被含日期的“菲空军24日证实”误拦。修正日期处理并补测试后，只再验飞机事故一组，保留1条。没有重复调用已通过的两组。

| 材料 | 最终结果 | 范围结论 |
| --- | --- | --- |
| 菲律宾两机相撞 | HTTP200，保留1、剔除1 | 保留来源链、事故地点及伤亡；另一个重复计划候选剔除 |
| 财富榜 | HTTP200，保留2、剔除0 | 两个人物各一条，保留来源及“第二次”，未将登顶／纪录拆两条 |
| 文物返还＋风格 | HTTP200，保留1、剔除1 | 标签前缀有可定位风格采用依据；重复计划候选剔除 |

本轮成功模型请求12次（诊断标题2、最终三组3、最终单例1、档案6），另有2次失败标题请求尝试；无法确认失败请求是否到达模型，不将其虚报为成功推理。控制计数包括失败预留，没有清零。

最终标题样例：

- 据新华社援引菲律宾媒体报道，菲空军证实两机23日在吕宋岛八打雁省训练时相撞致4人遇难
- 界面新闻：张一鸣6700亿第二次登顶，刷新首富纪录
- 界面新闻：钟睒睒缩水1200亿，4100亿退居第二
- 【快讯】据央视报道，国家文物局在澳接收2件北宋皇陵流失文物

这仅证明三组不再全部过滤，不代表标题质量整体通过。财富榜标题仍有“6700亿／缩水1200亿”的金额单位、对象省略，需编辑评价；风格采用片段可定位不等于符合度独立验真。模型仍可能生成重复计划，服务端继续剔除。滚动窗口变化仍可能使档案失效。

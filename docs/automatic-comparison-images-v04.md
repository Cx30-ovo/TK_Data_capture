# 同事件竞品对比：双方封面原图接入 v0.4

## 行为

用户主动启动新批次时，后台针对选中作品读取现有封面地址，并行读取双方图片；成功图片标记 owned/competitor，与文案、已有封面缓存及有效快照一并送至 `config.ai_config` 所指向的同一个模型。使用 OpenAI 兼容消息中的 `image_url` 内联 data URL，不另调用视觉模型，不要求用户先生成识别缓存。每对仍最多一次模型请求，没有自动重试。

单侧或双侧图片失败不会阻止文案、已有有效缓存和快照分析。只提供成功侧的原图证据 ID，缺少原图不得伪造视觉依据；如果引用不存在或不可用图片，封面子项独立拒绝。已有缓存必须标注此前识别，不能冒充本次看图。页面分别展示双方原图发送状态和失败类别，原图引用区别于缓存标签。

## 读取、边界与绑定

- 封面地址只从只读库中、通过作品身份与材料 SHA 校验的作品获取，不接收客户端任意图片地址。
- 下载仅允许平台图片 CDN 的 HTTPS 地址，重定向逐跳校验，最多两次跳转。不传模型认证、登录 Cookie，不使用环境代理，不访问本机或内网地址。
- 单图原响应上限 8 MiB、图像像素上限 2,000 万，支持 JPEG/PNG/WebP。解码后去掉元数据，等比缩放至最长边 512，转成 JPEG 内联发送；模型请求 detail=low。编码图上限 512 KiB。单图读取与解码总等待上限 15 秒，双方并行。
- 输入预算保留双方图片每张 2,048 token 的保守余量，最终组装材料再次检查上下文；输出仍最多 4,000 token 且不超过配置。不静默删除文案/快照来凑预算。
- 存档记录原响应字节 SHA、实际发送 JPEG SHA、尺寸、字节量、读取时间和封面地址 SHA；不将原始地址、图片 data URL 或认证写进任务存档。原图字节仅存在于当前任务内存，不写材料库或新增表。
- GET 历史记录与幂等重放不下载图片、不重新调用模型。GET 复核原截止时间的文案、封面地址、缓存与快照，并复用当时图片哈希绑定；不验证远端同 URL 的图像字节后来是否变化。已发送图片当时的哈希保留，无法仅凭哈希还原图像。
- 封面读取期间收到停止请求，不启动模型请求。图片读取后再次核对角色、模型配置；模型后再次核对材料，已变化不保存旧结论。

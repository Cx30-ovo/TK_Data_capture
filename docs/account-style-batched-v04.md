# 账号风格分批分析 v0.4

已修正500篇单次输入导致模型上下文超限的问题。当前模型返回的容量为32768 token；此前400发生在推断前，并非引用错误。

## 流程

人工点击更新 → 最多500篇按时间等距取样 → 每批最多50篇并按上下文预算进一步拆分 → 各批观察、代表作品及逐篇主题 → 统一汇总 → 服务端合并主题计数 → 全部通过后追加历史快照。

- 当前500篇计划为10批加1次汇总，不将500篇原文再次送入汇总。
- 预留系统提示、结构化输出Schema、消息开销及最多3000输出token。默认上下文32768，可用AI_CONTEXT_WINDOW显式配置。
- 严格JSON Schema约束分类数组恰好等于该批篇数，整数类型及引用范围仍由服务端复核。
- 汇总只接收精简批次观察、代表作品ID与主题计数。逐篇归类保留在服务端，主题合并不能漏项、重复或新增作品。
- 单次最多12批加1次汇总，每次请求不超过90秒，整体不超过900秒，无自动重试。
- 任意批次或汇总失败，不保存半成品、不覆盖旧档案，提示具体失败阶段。再次点击会重新执行，不提供断点续跑。
- 仅点击更新才调用模型；GET不调用模型、不触发采集。
- 未新增表或迁移。现有AI结果表仅在完整成功后追加快照。

## 限制

上下文字节估算为保守预算，并非模型tokenizer精确计数；仍会在模型拒绝时停止并保留旧稿。新模型须支持当前JSON Schema结构化输出。分批结果为标题级推断，跨批合并可能损失细节，不能当作事实核验或真实受众画像。

刷新页面后点击更新，才会执行新的正式分析；旧档案仍可阅读。完整批次可能需要数分钟。

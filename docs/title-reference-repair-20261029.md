## 修复结果

已修复此前确认的两项工程缺陷：

1. 模型不再复制 64 位片段哈希。请求中原文片段编号为服务端分配的 `u1` 等短编号，响应 Schema 中用本次请求的枚举限定；服务端精确映射为原 SHA 绑定后再校验、保存。`f1u1`、不存在编号、旧式拼接哈希均拒绝，不猜测修正。
2. 阶段校验报错带稳定错误码及字段路径，失败请求记录保留 `{code,path}`，不保存模型地址、凭据、请求头或整段模型原始文本。新增原文编号、片段归属、事实身份/数字/限定词、重复事实、计划及复核关联、输出 Schema 等诊断。

重验进一步定位到同主事实重复计划：最终版本剔除后续重复计划，并拒绝其关联标题，保留首个有效计划，记录 `omitted_plans`，不放宽“一主事实一计划”。标题的角度证据也必须属于计划引用的事实，避免借另一个事实的片段规避限定词。

没有修改客户端请求、数据库 Schema、采集或匹配算法，没有删除历史结果、清零预算或自动重试。旧幂等结果仍按旧结果重放。

## 未决问题

1. 独立事实归并仍依赖模型，跨片段近义或高度相关事实拆分不稳定。最终样本重新出现同一人物“登顶/纪录”分离，不能继续仅依靠模型一次输出宣称解决。
2. `required_terms` 把模型选择的长短语按逐字匹配强制保留。单一事实样本要求同时出现完整消息归因、证实日期、事故日期、地点、训练场景和伤亡短语，导致可读标题被过滤为空；是否语义遗漏或只是允许改写的表达差异，因未存被过滤标题正文无法进一步确定。
3. 风格档案已过期，不能据本轮结果判断真实风格采用质量。保持阻止状态正确，但验收依赖有效档案。
4. 本轮没有保存不通过候选的完整原始正文；后续若需分析语义误报，应明确有范围的保存策略，不能只靠原因码推出具体正文。

## 建议

先将“必须保留的事实限定”与“允许改写的来源/背景表达”分开设计，并建立同一事件中主体、动作、结果的事实聚合准则及反例。继续保留严格来源和事实引用，不通过关闭校验来换取通过率。风格验收前由用户更新账号档案。

本轮停止追加模型调用，不扩大预算，不宣称收口。现存代码已修复工程缺陷并在本地生效，标题质量仍需下一轮针对性改进后重验。

# 抖音浏览器会话与快照修复

## 适用问题

同一网络下，已登录浏览器能正常打开作品，但独立程序请求返回
`Blocked by ArgusSecurityPlugin Uifid Not Found` 或 `Sign Invalid`。
这说明浏览器能访问页面，并不代表复制 Cookie 后的独立请求具有相同的会话状态。

## 请求路径

- 直连且有浏览器上下文时，作品详情和账号作品列表复用专用 Chrome 中已有的抖音页签，不为每个请求新建标签。
- 读取网站正常加载页面产生的接口响应；不自行伪造或重放平台的校验标识。
- 详情按作品 ID 匹配，列表按账号 ID、请求游标匹配；允许正式 `douyin.com` 子域，但拒绝其他域名。
- 账号列表通过页面正常滚动获取后续页；每个客户端的页面操作间隔至少 5 秒。
- 平台拒绝后直接返回错误，不再额外发一次 HTTP 回退请求。
- 结束任务时仅移除响应监听和分页状态，不关闭复用的抖音页签。没有可用抖音页签时提示先打开，不占用 WebUI 或其他页面。
- 服务启动是例外：先准备专用抖音页签，再启动自动监控。已有抖音页签直接复用；首次 Chrome 的 `chrome://newtab/` 空页面可用于打开抖音；只有 WebUI 或其他网站时，在同一个专用 Chrome 中补开一页。启动时将抖音页签置前，采集期间仍然不新建请求页签。
- 普通账号爬虫先完成列表翻页，再依次跳转作品详情，避免同一页签的详情导航打断分页。
- CDP 管理器释放连接时保留 Chrome 的共享上下文；只有该管理器新建的上下文才会关闭。普通退出不结束共享 Chrome，显式退出进程也只处理本管理器持有的浏览器进程。
- 使用代理时保留原 HTTP 请求路径，浏览器路径不替代代理传输。

客户端同时在请求前从真实浏览器更新 Cookie 和会话标识，避免端点复制的请求头继续使用登录前的数据；浏览器版本取自实际 User-Agent。

## 风控退避与数据完整性

将部署端原有的退避保护一并纳入版本管理：识别风控响应后暂停后台发现和快照请求，首次 30 分钟，连续失败按倍数延长，最多 6 小时。
快照批次遇到风控立即停止后续请求；成功发现作品或完成快照后重置退避。
退避状态目前保存在进程内，重启会重置，不代表平台风控已经解除。

快照必须返回对应作品 ID，并包含点赞、收藏、评论、分享四项指标。缺字段属于失败，不能当成零写入；真实零值可以正常入库。
补采使用实际采集时间，不推算或伪造封控期间历史时刻的指标。

## 验证与维护

### 全局页签锁与采集控制

- `browser_data/douyin-tab.lock` 使用操作系统文件锁，在同一项目的 API 监控、普通抖音爬虫进程之间互斥。整个扫描、详情采集和资源清理期间持有锁；嵌套请求复用租约。进程退出后系统释放锁，不删除锁文件。
- 等待锁最多 30 秒，超时显示“抖音页签忙碌”，不是风控；等待期间可以安全停止。用户手动切换或关闭页签不能被程序锁住，检测到后提示恢复页签，避免继续使用无效分页状态。
- 账号监控和任务中心显示本轮账号、阶段、扫描页数/作品数、已保存数量、快照处理数和耗时。发现总量未知，不展示虚构百分比；快照按本批任务数显示真实进度。
- “安全停止”暂停自动发现与快照，等当前请求和数据库保存完成：发现保存已扫描作品，快照保存当前作品，后续任务保持待执行。“恢复监控”不绕过风控冷却。暂停和进度保存在当前服务进程，重启会重置；这是监控控制，不替代普通爬虫原有的停止按钮。
- 发现中途出错仍保存已取得的有效作品，并返回部分成功；未完整扫描不更新账号的发现完成时间。风控中止整批；登录失效/页签切换/连接中断暂停监控等待人工处理；网络超时停止当前批次；已删除作品终止其任务；缺字段不按零写入。
- `GET /api/monitor/execution` 获取状态；`POST /api/monitor/execution/stop?run_id=...` 安全停止；`POST /api/monitor/execution/resume` 恢复监控。过期 run_id 返回 409，不影响新任务。已知采集失败以 `status/error_code/reason/action` 返回，不再显示未解释的 500。

新增离线回归：`tests/test_monitor_control.py`，包含真实子进程文件锁、等待停止、资源释放、部分保存和控制 API；不访问抖音或生产数据库。

```sh
uv sync --frozen
uv run --frozen pytest -q tests/test_douyin_browser_session.py tests/test_monitor_session_safety.py tests/test_monitor_repository.py tests/test_monitor_hot_rank.py
```

上述回归测试使用模拟浏览器与测试数据库，不需要真实登录凭据，也不会请求目标平台。
部署端曾验证作品详情、账号第二页，以及一轮 33 个快照完成、零失败和零重试；这仅是验证时点的结果，不保证未来平台访问持续可用。

该逻辑依赖正常网页和页面发出的接口响应。如果平台页面结构变化或要求验证，应保留错误和退避，检查正常登录与页面访问，不提高请求频率或绕过访问控制。
提交中不包含 Cookie、密码、签名值、运行日志、浏览器档案或生产数据库。
